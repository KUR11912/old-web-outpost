# 扩展地图浏览器验收

验收日期：2026-11-10。运行地址：`http://127.0.0.1:5180/`。

## 结果

完整浏览器回归 14 项通过，页面脚本错误为 0。另以本机硬件加速 Chrome 连续走完三段主要路线，均无卡住、穿地、意外涉水或存档位置回退。测试使用独立临时浏览器上下文，未修改用户已有浏览器存档。

## 实际行走时间

下列数据来自真实 WASD 按键、浏览器实际位置采样及墙钟计时，不是距离除以配置速度的估算。各段起终点为道路节点／地点门前；第一段从驿站前道路 `(0, -2)` 起算，出生点到该节点的起步不计入。转向、阅读和截图时间不计入按键行走时间。

| 路段 | 采样行走距离 | 实际按键行走 | 包含转弯指令间隙的总耗时 | 平均帧率 |
| --- | ---: | ---: | ---: | ---: |
| 旧网驿站前道路 → 回声档案馆门前 | 53.64 m | 22.39 秒 | 22.46 秒 | 239.96 FPS |
| 回声档案馆门前 → 桥梁中心 | 59.79 m | 25.00 秒 | 25.12 秒 | 239.33 FPS |
| 桥梁中心 → 记忆灯塔门前 | 45.72 m | 19.12 秒 | 19.21 秒 | 238.55 FPS |

这三段实际顺序游走约 66.5 秒，不含停留。自动键盘控制以 60ms 间隔观察位置，因此转弯处会有少量越过目标后修正，采样距离略长于路径中心线。完整坐标和采样结果见 `map-hardware-timing-report.json`。

硬件验收环境：Windows、本机已安装 Chrome，1440×1000 视口，deviceScaleFactor=1。WebGL renderer：

`ANGLE (NVIDIA, NVIDIA GeForce RTX 5070 Ti Laptop GPU (0x00002F58) Direct3D11 vs_5_0 ps_5_0, D3D11)`

三段采样中超过 50ms 的帧均为 0，最长帧分别为 4.5／8.6／8.7ms；现有帧时间上限没有截断移动时间。硬件实测速度为 2.39–2.40m/s，与配置 2.4m/s 一致。

## 软件渲染对照及限制

首次完整回归强制 `--use-angle=swiftshader`，即 CPU 软件 WebGL；同样通过所有功能检查，但三段按键时间为 32.58／28.92／23.73 秒。该轮没有记录逐帧数据，不能直接给出其平均 FPS。结合硬件复测，以及当前主循环将单帧时间截为最多 50ms 的实现，低帧率时行走时间会延长。此差异已记录，不把软件渲染时间当作正常硬件预览时间，也不声称所有电脑都达到上述帧率。

## 检查内容

- 原有五个 GLB（树、石、草、道路、驿站）实际完成加载；固定出生点和唯一驿站保留。
- M 打开真实场景俯视全图；查看全图时 WASD 不移动，关闭后须明确点击恢复。
- 连续行走三段道路，运行中眼高保持 1.65m，地面与桥两端没有卡点。
- 桥外西岸与东岸都阻挡涉水；桥梁东西双向可通行，南北护栏阻挡进入河道。
- 西、东、北、南四方向边界阻挡，不能越出配置地图。

- 邮箱仍可通过 E 调查，获得同一 ID 的唯一线索；原始图片正常加载（自然宽度594像素），刷新仍保留领取状态。

## 重复运行

先启动项目服务，再执行（使用本机运行时附带 Playwright）：

```powershell
$playwrightEntry = Join-Path (Split-Path (Split-Path (Get-Command node).Source)) 'node_modules\playwright\index.mjs'
node '.\qa\map-browser-test.mjs' $playwrightEntry 'http://127.0.0.1:5180/'
node '.\qa\map-browser-test.mjs' $playwrightEntry 'http://127.0.0.1:5180/' --hardware --timings-only
node '.\qa\map-browser-test.mjs' $playwrightEntry 'http://127.0.0.1:5180/' --hardware --photos-only
```

默认完整回归使用软件 WebGL，输出 `map-browser-report.json`；硬件计时输出 `map-hardware-timing-report.json`。最后的取景命令恢复较完整的地点截图，输出 `map-photo-report.json`。

# 旧网驿站

《网络梗考古》的独立第一人称自由探索原型。Vite + TypeScript + Three.js，目前包含84×74米地图、五个可拾取的探索收藏、邮箱与档案馆旧终端；原28×28米驿站区域位于西南侧。保持基础Y2K低多边形效果，未改动原字符网页游戏或Blender工程。

GitHub Pages 试玩地址：[旧网驿站](https://kur11912.github.io/old-web-outpost/)。网页会把进度保存在当前浏览器中；线上地址与本地地址各自保存进度。

## 中文版与英文版

- `zh-cn`：保留英文翻译前的中文版快照，提交 `754697f`。
- `main`：继续维护中文版，试玩地址保持 [中文版](https://kur11912.github.io/old-web-outpost/)。
- `en`：完整英文版，试玩地址为 [English edition](https://kur11912.github.io/old-web-outpost/en/)。界面、提示、档案正文、地图及场景文字均为英文；原始梗图和水印保留，配有英文说明。

两个线上版本保留相同物品 ID 和存档格式，使用当前浏览器同一份进度。切换语言可继续探索；在任一版本确认清空进度，也会清空另一语言版本的共享进度。音量与音效偏好同样共享。本地服务与线上站点仍各自保存。

## 直接运行

当前电脑双击 `启动旧网驿站.cmd`，会检查已有服务，必要时在后台启动并打开 **http://127.0.0.1:5180/**。关闭浏览器不会关闭后台服务；重启电脑后再次双击即可。

也可在本目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm run dev
```

推荐 Node.js 24；包管理器在 `package.json` 中固定为 pnpm 11.25.0，与线上构建一致。本机已有依赖，启动脚本优先使用 PATH 中的 Node，再尝试已安装的 Codex 附带 Node。脚本不下载软件。若把项目复制到其他电脑，应先安装 Node.js 和 pnpm，再执行上面的依赖安装命令。

构建：`pnpm run build`；预览构建结果：`pnpm run preview`，然后访问 **http://127.0.0.1:5180/old-web-outpost/**（同用 5180 端口，先关闭开发服务）。开发模式仍使用 **http://127.0.0.1:5180/**。不能直接双击 `index.html`，GLB 和模块需要通过 HTTP 服务加载。

`vite.config.ts` 为生产构建和构建预览设置 `/old-web-outpost/`，开发服务器保留根路径。模型和线索图片使用同一资源前缀。

提交并推送到仓库 `main` 或 `en` 分支后，[双语版本发布流程](https://github.com/KUR11912/old-web-outpost/actions/workflows/deploy.yml) 会分别安装锁定依赖、检查类型并构建两个分支，将中文版放在根目录、英文版放在 `en/`，合并为同一份 Pages 发布产物。无需将英文游戏内容合并进 `main`。`zh-cn` 为保留快照，不触发发布。也可以在 Actions 页面点击 **Run workflow** 手动重新部署。仓库 **Settings → Pages → Source** 使用 **GitHub Actions**。

本地复现线上构建：

```powershell
pnpm install --frozen-lockfile
pnpm run build
```

只发布构建后的 `dist/`；Blender 源文件、参考图和 QA 记录保留在源码仓库中，不进入游戏站点。部署配置参考 [Vite 官方 GitHub Pages 指南](https://vite.dev/guide/static-deploy.html#github-pages) 与 [pnpm 官方安装 Action](https://github.com/pnpm/action-setup)。

## 操作与完整流程

1. 点击“点击开始探索”，进入鼠标锁定；若浏览器限制锁定，自动改用拖拽。也可直接点击“拖拽模式进入”。
2. WASD 行走，鼠标转头；拖拽模式按住左键转头。Esc 暂停并释放鼠标。
3. 靠近黄色漂浮文件夹自动发现老梗名称，无需按键。提示只出现一次，文件夹消失，探索保持继续；拾取不会解锁真实梗图或资料。
4. 邮箱仍可在靠近并看向时按 E 阅读虚构留言，但不发放老梗。图片 ID 沿用 `missing-caption-image`；旧存档明确保存的文件夹库存会保留，只有对应已拾取文件夹才从地图隐藏。
5. 按 B 打开收藏背包。未查询条目只显示名称、“IMG / ARCHIVE”占位图和终端查询提示；已查询条目显示完整档案。仅阅读邮箱不会获得老梗。
6. 刷新恢复位置、视角、调查状态与线索。关闭窗口后须再次点击场景/进入按钮才能移动。
7. 按 M 或点击“全图”查看同一 3D 场景的俯视全图。全图暂停行走，返回后明确点击继续；沿石板路向北到回声档案馆。
8. 到档案馆门前旧终端，靠近、看向它并按 E 打开“老梗检索”。输入已收集的梗名，点击搜索或按回车；成功显示资料即自动更新该条背包档案并保存，无需领取。搜索期间输入字符不触发游戏快捷键。
9. 沿现有道路寻找五个探索收藏；左上进度统计已收藏数量，按 B 查看统一收藏背包。
10. 断链桥继续开放，不需要完成调查或整理线索才能通过。

顶部“清空游玩进度”点击后需要再选择“确认清空”：清除本游戏的收藏、查询、邮箱与调查进度以及旧收藏修正备份，恢复五个文件夹并回到出生点。音乐音量和音效偏好保留；取消不会清除进度。窗口打开、Esc、切换窗口/标签页时均停止移动。没有跳跃、奔跑或战斗。

## 收藏与资料解锁（当前规则）

每个梗以稳定 `memeId` 关联场景 `pickupId`。收集和查询是两个独立状态：未拾取不出现在背包；已拾取未查询仅显示名字与统一占位；已查询可随时在背包回看真实图片和完整资料。查询不会增加收藏数量、播放拾取音效或发放物品。

检索只做NFKC全半角归一、去除首尾空白和英文字母大小写归一；其他写法必须在配置中明确列为别名，不做模糊匹配。空输入、未匹配、未拾取、终端资料暂缺分别反馈，且不修改解锁记录。中文输入法确认候选的回车不会提交；再次按回车才检索。只有场景旧终端交互能开启搜索，背包不能远程查询。

配置位置：`src/meme-archives.ts` 的 `MEME_ARCHIVES` 配置名称、显式别名、资料可用状态和对应资料卡；`src/archive-data.ts` 的 `CLUES` 保存图文和来源说明；`src/pickup-data.ts` 保存稳定拾取物与位置。将来补齐资料需提供真实图片、含义与语境等内容，配置对应卡片后再启用档案，不能只将占位条目标记为可用。

| 梗名 / memeId | 当前资料 |
|---|---|
| 蓝瘦香菇 / `blue-mushroom` | 可查询：复用已有图片、读音便笺、语境和改编说明；原图片出处、原始录音未核验的限制仍明确保留 |
| 友谊的小船 / `friendship-boat` | 可查询：企鹅漫画、2016年春流行背景、含义与使用示例；区分漫画作者与句子的最早发明者 |
| 你是GG还是MM / `gg-or-mm` | 可查询：早期聊天缩写、时期与语境；旧版QQ图片仅作时代背景，不是该问句的原始聊天记录 |
| 厉害了我的哥 / `awesome-my-bro` | 可查询：代表性表情图、2016年流行背景、赞叹及反讽语境；保留起源有不同版本的说明 |
| 你是魔鬼还是秀儿 / `devil-or-showoff` | 可查询：相关表达与改编歌的区别、使用示例，以及“魔鬼”“秀儿”两张相关配图；最早上传者尚未核实 |

四份新增档案按用户提供的 `old-web-meme-pack.zip` 接入，原始MD、JSON和图片保存在 `meme_asset/source/old-web-meme-pack/`。实际运行读取 `src/archive-data.ts` 内的本地配置，图片复制到 `public/assets/memes/`；未重新裁切或重绘。该包提供的年代、作者和出处仅按原资料表述接入，尚未确认的信息继续保留，不新增精确首发结论。蓝瘦香菇原有内容保持不变。

`ClueCard` 的 `period`、`example`、`contextNote` 对应时期、情境示例、使用语境；`gallery` 保存每张图的本地路径、说明、用途、署名、来源页、原图链接和不确定性。正文展示完整比例的配图，点击可打开大图并滚动查看；“返回档案”恢复阅读位置和已展开的资料说明。图片署名、出处说明、尚未确认的信息与来源链接统一放在“资料说明”折叠区。所有这些字段仅在成功查询之后出现在终端和背包详情中。

存档仍使用 `old-web-outpost:save:v1`、`collectionVersion: 2` 和独立 `queriedMemes`。读取时以显式 `pickupInventory` 为准，空数组也表示没有收藏；只有缺少这个字段的旧存档，才从有效 `collectedPickups` 恢复库存。历史 `clues` 和 `memes` 不会凭空生成文件夹或收藏；旧线索记录保留，`memes` 与地图隐藏记录按实际库存同步。

资料解锁只保留同时存在于实际库存中的显式 `queriedMemes`。包括 `echo-meaning-note` 在内的蓝瘦旧调查线索都不再推断为已查询；没有显式查询记录时，已拾取条目仍须在旧终端搜索。真实库存和对应的明确查询进度继续保留。邮箱已读、旧调查记录、任务答案、位置及音量偏好不变。

如果旧版本已经把误生成的收藏写入显式库存，程序无法仅凭现有数据区分真实拾取和错误迁移。可点击顶部“清空游玩进度”，再选窗口中的“修正旧收藏”：逐条选择“没捡过，放回地图”或“已捡过，资料改为尚未查询”，其余保留现状。应用前会在 `old-web-outpost:save:v1:before-collection-repair` 保存收藏备份；修正后可撤销，恢复备份中的收藏与查询记录，并保留修正之后新获得的收藏和查询进度。当前位置、任务记录和音量不受修正影响。这里不需要执行“确认清空”。

`src/pickup-data.ts` 的每项集中包含 `id`、`memeId`、`name`、`description`、`icon`、`location`、`position` 和截图编号 `marker`。原四个占位文件夹现分别绑定 `friendship-boat`、`gg-or-mm`、`awesome-my-bro`、`devil-or-showoff`，没有新增、移动或复制场景实例。每项在 `MEMES` 中关联独立收藏卡，卡片位于 `src/archive-data.ts` 的 `CLUES` 中，但不加入任务专用的 `CLUE_ORDER`。四条已补齐用户资料包中的图文；背包未查询时仍使用统一“IMG / ARCHIVE”占位，成功查询才显示本地配图和正文。`getPickupContent` 每次从配置读取展示内容，存档只记录稳定ID和独立状态，因此已持有条目可以查询新资料，无须重新拾取。

以稳定 `pickupId` 保存 `pickupInventory` 所有权，收集时同步记录 `memes`；查询成功才增加独立 `queriedMemes`。先确认入库再隐藏场景实例。旧占位收藏依据原记录解析当前绑定，已领取的文件夹保持消失，不需要重置存档；未知ID不会发放物品。

## 脚步与拾取音效

草地使用柔和的踩草/摩擦声，原驿站步道、扩展石板路和石桥使用短促的硬地脚步声。每种材质有5个本地WAV变体，随机播放且同一材质不会连续重复同一个样本；附带轻微音高、音量变化。素材来源与CC0许可见 `public/audio/footsteps/` 中的说明。

脚步按碰撞处理后的实际位移触发：起步移动0.12米后发出第一步，此后每1.12米一步，当前2.4米/秒步速约每0.47秒一步。原地转头、按住方向撞墙、停止、Esc暂停、全图、背包、调查窗口和页面失焦时均停止，尾声用15毫秒淡出避免爆音。声音在点击进入探索后解锁，不自动播放。顶部“音效：开/关”统一控制脚步和拾取声并记住偏好；默认总线音量30%，沿用原有静音偏好，不修改游戏进度存档。

五处老梗文件夹成功收入背包时，播放一次约0.32秒的原创街机金币风格上行双音。`src/pickup-chime.ts` 同步合成PCM，无外部下载或音频加载等待。只有 `collectPickup` 返回成功才触发，已收集物品、刷新恢复与静音期间的拾取均不补播。停步不会截断提示音；暂停、静音或失焦会让它一起淡出。它与脚步共用同一个音频上下文和低音量总线。

`src/footstep-surface.ts` 按真实铺装边界判断脚下材质，`src/footsteps.ts` 负责节奏、素材解码与播放。更换样本请保留 `grass-01.wav` 至 `grass-05.wav`、`stone-01.wav` 至 `stone-05.wav` 文件名。

验证：`node --test qa/footstep-surface.test.mjs qa/footsteps.test.mjs qa/pickup-chime.test.mjs`；浏览器走测为 `qa/footsteps-browser-test.mjs` 和 `qa/pickup-audio-browser-test.mjs`，参数依次为Playwright入口绝对路径和本地游戏URL。

## 背景音乐
